# PR #24：高算力 state 池调整方案

状态：已实现并通过本地前后端验证。具体运行约定见 docs/conventions/codex-turn-state.md。

## 已确认

- 合入最新 main，功能重叠以 PR #24 的主动探测、按模型隔离、失效观测逻辑为准；保留无关主线更新。
- 按账号套餐分类：Pro 20x / Pro 5x / Plus 的正常长度为 292，Team 的正常长度为 332；非空的其它长度异常，其中已观测到 312 / 356。这些是维护者实测判据。
- 保留每账号、每个实际出站模型一个当前候选，不做多候选轮换。
- 保留串行探测、25 次预算、每次 10 秒，以及 1 小时 TTL、提前 5 分钟续期。
- HTTP 使用请求头；WS 一律优先使用 response.create 的 client_metadata["x-codex-turn-state"]，命中本账号候选时覆盖旧值，支持非设备指纹账号。
- WS 上游握手清除该头，包括客户端透传和账号头覆写；长连接按每次发送更新，保留现有连接池复用策略。
- 增加管理员状态池页面：展示已配置模型，默认筛选 gpt-6-astra，按账号/实际模型显示卡片。
- 页面保留手动刷新：后台获取新候选，成功后替换，失败保留仍有效的旧值。
- 本功能只配置一个全局动态代理；所有账号获取候选都使用它，普通业务流量仍使用账号日常代理。

## 已落实的行为

- “上游没有回铸 state”不等于失效。维护者实测有效本账号值被接受时不回铸；不能要求每个请求都有返回头或 metadata。
- 观测必须覆盖 HTTP 响应头、SSE 和 WS 原始事件；维护者报告了 codex.response.metadata，并兼容原有 response.metadata，已按脱敏原始样本兼容顶层 headers，不能只改长度常量。
- 模型降级判定按实际请求模型解释：请求 gpt-6-astra、返回 gpt-5.6-luna 才是已知降级；如果本来请求 luna，不能因名字中有 luna 就清理候选。
- 凭据、账号与模型仍隔离；共享代理不意味着跨账号共享 state，也不以其它账号的候选兜底。
- 全局代理变更建议只影响后续探测，不清空已有有效候选。旧的账号级代理配置不能静默选一个作为全局值；需显式配置全局代理，缺失/不可用时显示原因，不直连兜底。
- 页面区分“当前候选有效性”和“后台刷新状态”：有效候选可以同时处于续期中或续期失败，不能误显示为已失效。
- 页面建议展示账号、套餐、实际模型、正常/实际长度、到期倒计时、最近探测及失效原因；原文与复制仅通过管理员专用接口按需读取，通用 DTO 和导出继续脱敏。

## 最终选择与样本

- HTTP 优先，HTTP 200 未返回 state 时，下次尝试切换全新 WS；两种协议共享每模型 25 次预算，每次 10 秒。
- 未知套餐显示未知，不猜测；耗尽后只暂停该模型探测；TTL 从成功获取时计算。
- 维护者原始样本：`{"type":"codex.response.metadata","headers":{"x-codex-turn-state":"<state>"}}`。请求载体是 `client_metadata`，响应载体是事件顶层 `headers`。
- 有效值可跨同一连接的两轮复用。有效值不回铸时保留；安全缓冲和 faster-model 头不表示失效。
- 已补充套餐别名、HTTP/WS 共用预算、逐轮复用、全局代理隔离、手动刷新保留旧值、页面交互等回归测试。
