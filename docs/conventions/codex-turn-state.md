# Codex turn-state 候选

适用于持有独立凭据的 OpenAI OAuth / Setup Token 账号。以下提前失效判据来自维护者实测口径，不把固定字节长度或跨请求复用视为 OpenAI 官方协议保证。

## 模型与续期

- 模型集合取账号模型限制映射的目标模型，归一化为实际出站模型 ID；探测、缓存、HTTP 请求和 WS 帧只使用该 ID，不再次应用账号映射。
- 保留按账号、模型串行探测。单模型最多连续尝试 25 次，单次超时 10 秒。历史 50 次失败记录按已耗尽新预算处理；“继续续期”只重置失败预算，不删除仍有效的候选。
- 通过配置的动态代理获取候选；仅接受 HTTP 200 且响应 `X-Codex-Turn-State` 长度为 292 字节。探测收到响应头即关闭响应流。
- 候选 TTL 为 1 小时，到期前 5 分钟续期。续期失败仍保留未过期的旧候选；实际凭据、候选代理或账号类型变化遵守已有身份隔离规则。

## 日常请求的提前失效

只对本次实际发送的账号候选进行观测。以下任一信号使该账号、该模型的候选提前失效：

1. 上游原始 `response.created` 中 `response.model` 为 `gpt-5.6-luna`。
2. 流中出现结构化 `server_is_overloaded` 错误，包括 HTTP 200 中的失败事件；普通输出引用这段文本不算。
3. 上游响应头或 WS `response.metadata.headers` 中的 `X-Codex-Turn-State` 长度为 312 字节。

正常 `response.completed`、缺少 state 头、其它错误或其它模型差异都不额外推断为上述失效。HTTP SSE/JSON、WS HTTP 桥以及 WS 三条转发路径在上游模型名称回写前观测；不改写响应内容。

失效时清除该模型的候选和失败预算，唤醒已有串行探测循环，通过动态代理重新获取。只清理请求使用的那一代候选；其它模型及并发续期产生的新候选不受迟到响应影响。长期 WS 连接每轮读取最新候选，并在实际出站帧中注入，避免继续使用连接建立时的旧快照。

## 持久化与编辑

- 后台续期、观测失效和手动重试使用数据库条件更新，同时核对凭据、配置及原缓存/失败记录，避免并发覆盖。
- 普通账号编辑不因请求携带未变的 credentials 而清理缓存。数据库更新在行锁内保留当前受管状态，避免旧表单覆盖续期结果或复活已失效候选。
- 缓存继续从管理 DTO、导出和账号复制中排除；日志不记录原始 state。

## 与主线旧功能的兼容

- 本功能开启时优先于主线 openai_turn_state_auto / openai_turn_state_override，候选尚未就绪也不回退到旧池。旧自动池不再观察该账号的响应、淘汰候选或停用账号。
- 本功能关闭的账号保留主线手填覆写及 HTTP 自动接管；两套受管缓存字段均保留各自的编辑保护。
- 主线新增的使用记录字段继续保留；本功能实际注入时，turn_state_source 记录为 probe。WS 按发送帧更新标记，不能将上一轮的注入来源留给未注入的下一轮。
