# Codex turn-state 候选池

适用于持有独立凭据的 OpenAI OAuth / Setup Token 账号。长度和复用规则来自维护者实测，不作为 OpenAI 官方协议保证。

## 配置与获取

- 管理员在「高算力 State 池」页面配置一个全局动态代理，所有账号的候选探测使用它。普通业务流量仍用账号代理。缺少或不可用时不探测、不直连兜底；旧账号级探测代理不再生效，升级后需显式配置全局代理。
- 模型集合取账号限制映射的目标模型，归一化为实际出站 ID；探测、缓存与注入不再次应用映射。每账号、模型只保留一个当前候选。
- Plus / Pro 20x / Pro 5x 正常长度为 292，Team 为 332；兼容仓库的 chatgptpro / prolite 等套餐别名。未知套餐不猜测长度，不自动探测或注入。
- 串行探测，每模型最多连续 25 次，每次拨号、发送、读取合计最多 10 秒。HTTP 优先；HTTP 200 未返回 state 时，下次尝试切换全新 WS 连接，仍共用总预算。非空异常长度不触发协议切换。
- HTTP 读取响应头后关闭流；WS 仅从 response.metadata 或 codex.response.metadata 事件顶层 headers 的 x-codex-turn-state 获取候选，不读取握手响应。每次 WS 探测均关闭连接，不占用业务连接池。
- TTL 从成功获取时算 1 小时，提前 5 分钟续期。续期及手动刷新失败保留仍有效的旧值，成功才替换。耗尽预算暂停该模型，允许人工重试，不停用整个账号。

## 注入与提前失效

HTTP 在最终请求头注入。所有 Codex WS 发送边界在 response.create 的 client_metadata["x-codex-turn-state"] 注入，覆盖客户端旧值，支持非设备指纹账号；握手删除该头，包括客户端透传和账号覆写。长期连接逐轮读取当前候选，允许跨轮复用。

仅对本次实际发送的账号候选观测，以下任一信号使它提前失效：

1. 实际请求非 gpt-5.6-luna，而原始 response.created 的 response.model 为 gpt-5.6-luna。
2. 结构化 server_is_overloaded 错误，包括 HTTP 200 的失败事件；普通输出引用该文本不算。
3. 响应 state 非空且不等于本账号套餐的正常长度。

HTTP 响应头、SSE/JSON 以及 WS 原始事件均在模型名称回写前观测。兼容两种 metadata 事件名，读取顶层 headers；缺少 state 不算失效。安全缓冲和 faster-model 头不是失效信号，它们也可能伴随正常 astra 响应。

失效清除该模型候选、记录原因并重置预算，唤醒后台重新获取。条件更新只清理请求实际使用的那一代，迟到响应不能删除续期得到的新值。

## 管理与并发

- 状态池展示已配置模型，默认筛选 gpt-6-astra。候选有效性与探测进度分别展示；有效值可以同时处于续期失败状态。倒计时按服务器时间校正。
- 手动刷新后台执行，相同账号/模型请求合并。原始值只通过管理员专用复制接口按需读取，列表、通用 DTO、导出与复制账号继续脱敏；日志不记录原文。
- 后台续期、失效观测与重试使用数据库条件更新，核对凭据、配置、原缓存及失败记录。普通编辑在行锁下保留受管运行态，避免旧表单覆盖续期或复活失效值。
- 全局代理变更不清理有效候选；账号凭据、实际模型与账户归属仍隔离，不跨账号共享值。
- 功能开启时优先于主线旧自动池与手填覆写，未就绪也不回退旧池。关闭时保留主线逻辑，但 WS 值统一放帧内。使用记录在本功能实际注入时标记 probe，并逐帧更新。
