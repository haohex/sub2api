# Codex turn-state 候选池

适用于持有独立凭据的 OpenAI OAuth / Setup Token 账号。长度和复用判据来自维护者实测，不作为 OpenAI 官方协议保证。

## 配置与获取

- 账号编辑仅保留我们的候选探测开关和模型限制。PR25 的旧自动池和手填覆写配置不再生效，关闭我们的开关也不会恢复旧接管逻辑。历史使用记录保留。
- 管理员在高算力 State 池页面配置一个全局动态代理，所有账号各自获取候选；业务流量仍使用账号日常代理。缺少或不可用时暂停，不直连兜底。
- 模型集合取账号限制映射的目标 ID，不重复映射。每账号、实际模型只保留一个当前候选。
- Plus / Pro 20x / Pro 5x 正常长度 292，Team 为 332，兼容 chatgptpro / prolite 等别名；未知套餐暂停自动获取。
- 候选获取固定 HTTP SSE，单次请求整体超时 10 秒，从响应头或 response.metadata / codex.response.metadata 事件顶层 headers 获取。禁止回退 WS。业务 WS 的帧内注入保留。
- 获取、查询出口 IP 和管理端出口检测使用独立 HTTP Transport，禁止代理隧道复用，保留 SOCKS5H 远端 DNS。普通业务连接池不变。
- 每次获取后经同一代理独立查一次 IP，使用配置的第一个检测目标，超时 5 秒，不占获取次数。标记为“参考出口 IP（探测后查询）”，不能声称它就是前一次 SSE 的确定出口。

## 有效期与调度

读取 Fernet 的版本、格式及明文签发时间，不声称验证其签名。格式错误、签发时间超前超过 60 秒或已过期的值拒收。有效到期时间取签发时间加 1 小时、网关获取时间加 1 小时中的较早者；旧缓存也按此重新判定。

- 剩余超过 30 分钟：不自动获取，允许手动操作。
- 剩余 10～30 分钟（含 30、不含 10）：每轮最多 25 次，轮次完成后间隔 5 分钟；得到有效期更晚的新值即结束本轮。
- 剩余不超过 10 分钟时，对仍有有效候选的账号持续获取，不封顶；首次无值、候选提前失效或已经到期时也进入持续模式，但连续 25 次未取得有效候选后暂停 5 分钟，再开始下一轮。每次 SSE 和查 IP 流程结束后等待 1 秒。
- 轮次中进入最后 10 分钟，立即转持续模式；更新后按新的剩余时间重新选择模式。相同 token 或没有更晚有效期的候选不延寿、不替换有效旧值。
- 调度队列按到期时间公平推进，单进程最多 4 个获取任务并发，同账号最多一个在途任务，每次完成释放执行槽。关闭功能、账号停用或代理不可用时暂停，恢复后继续。
- 手动立即探测在非持续模式下执行一轮，最多 25 次；持续模式下合并操作，不启动重叠任务。
- 手动刷新在已有任务运行时保持排队，当前尝试结束后优先执行；没有有效候选时手动或自动失败同样遵守 25 次/5 分钟冷却，避免无效账号持续占满探测槽。

## 手动导入

账号卡片按当前选择的模型提供粘贴入口，提交后先检查长度、格式和时间，再携带输入值通过全局动态代理执行一次独立 HTTP SSE 验证。要求请求正常完成、服务模型与实际模型一致、没有失败/过载或异常返回 state；未回铸允许通过，回铸不同值则拒绝导入。

仅在新值有效期更晚、或当前没有有效候选时替换。校验失败、账号忙、凭据/配置变化或并发产生了更新候选时保留原值并说明原因。原文仅在校验期间使用，通过后进入受管缓存；通用审计同样脱敏，不进入事件日志或浏览器持久化存储。

## 业务注入与失效

开启受管候选后，HTTP 和 WS 的最终发送边界先删除客户端回带值，再只注入本账号、实际模型且仍有效的正常候选；没有候选时不发送任何 turn-state，也不借用关闭功能账号的旧值。调度器找不到有候选的账号返回 `high_compute_state_unavailable`（HTTP 503）。Codex WS 所有发送边界逐轮读取当前候选，注入 client_metadata["x-codex-turn-state"]，清除上游握手中的该头，支持非设备指纹账号。Messages 兼容桥在构造后恢复旧会话值时，也必须再次经过这个最终收口。

仅对实际发送的候选观测：返回 state 非空且套餐长度异常、实际请求非 luna 却在 response.created 返回 gpt-5.6-luna、或出现结构化 server_is_overloaded，条件清理本次使用的那代候选并重新获取。迟到响应不得清理已经更新的候选。

未回铸、正常完成和安全缓冲/faster-model 头不表示失效。invalid_encrypted_content 记录诊断，保留现有密文恢复，不单独清理候选。

## 页面、日志与持久化

- 每账号一张卡片，独立选择配置模型，优先 gpt-6-astra；轮询不重置选择，也不改变后台模型范围。
- 候选有效性与获取状态分别展示，含签发/获取/有效到期时间、模式、下一次获取时间、手动导入和分页日志。
- 状态池事件保留 7 天，每小时清理。逐次记录开始/结果、来源、轮次、代理标识及脱敏地址、参考出口、耗时、HTTP 状态、发送/返回长度、有效期和原因。失效观测、实际清理与并发跳过分别记录；不记录原始 state 或代理凭据。
- 使用记录新增可空的实际发送 state、请求时正常长度及发送/返回长度，HTTP/WS 按请求轮次采集；0 表示确认没有值，NULL 表示历史未采集。返回字段不拿发送值代填，页面只在返回缺失时回退展示实际发送值。
- 状态池卡片和使用记录统一显示长度徽标、state 前缀和复制入口；按账号套餐判定正常长度，正常为绿色，异常或过期为红色，缺少判定依据为灰色。使用记录优先显示上游返回值，没有返回时显示实际发送值。
- 缓存写入及失效清理使用数据库条件更新核对凭据、配置与原运行态；普通编辑仍在行锁下保护运行态，避免覆盖续期或复活已失效值。
